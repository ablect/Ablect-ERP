# Ablect Business Suite V1.0 commercial deployment

## Architecture decision

The current branch is an Electron desktop application with a React/TypeScript renderer and a Node/Electron main process using `mysql2`. It is not a Python backend and does not use PyInstaller. V1 should therefore be packaged with Electron Builder rather than introducing a second backend.

## Invoice sequencing

The authoritative invoice is generated by `electron/database/sales-service.js` from the transactional `sales_orders.id` auto-increment value. The renderer's invoice value is only a preview. Checkout does not trust the renderer to choose the permanent invoice number.

The transaction locks product rows, validates stock, inserts the sale, derives `INV-00001`-style numbering from the inserted ID, inserts sale lines, decreases stock, records movements/audit information and commits. Any failure rolls the transaction back. Concurrent checkouts cannot claim the same permanent invoice number.

Gaps after rollbacks are intentional and safer than reusing accounting numbers.

## Security

Passwords use salted Node `scrypt` hashes. Do not ship a hardcoded master password: a desktop executable can be inspected and a universal bypass would compromise every customer installation. ABLECT support recovery uses a signed, machine-bound, expiring recovery token. Keep the Ed25519 private signing key offline and ship only the public key.

If a future release introduces a Python backend, PyArmor can be applied before packaging. It is not part of the current Electron V1 build.

## MySQL startup

`electron/database/db.js` creates the configured database if necessary using bootstrap credentials, then the application pool connects using the restricted application account. Migrations create the schema and seed system data.

Production should use a restricted `ablect_app` account for normal operation. Do not run the ERP day-to-day as MySQL root. MySQL 8.x or MariaDB installed as a Windows service is recommended for V1; XAMPP is development-oriented.

## Packaged paths

Electron uses `app.getAppPath()` for read-only application resources and `app.getPath('userData')` for writable installation data. Do not use PyInstaller's `sys._MEIPASS` in this Electron project.

Writable files live under `%APPDATA%/AblectBusinessSuite`, including client configuration, printer profile, license and error log. Product uploads should also use the writable user-data directory rather than `app.asar`.

## Logging

`electron/logging.js` writes rotating JSON logs to `%APPDATA%/AblectBusinessSuite/error_log.txt`. It captures uncaught exceptions, unhandled promise rejections, database startup failures and IPC failures without showing a developer console in packaged builds.

## First-run wizard

The wizard collects the client business name, administrator account/password, first Xprinter profile and first product. It stores the printer profile and client branding in the Windows user-data directory and uses the existing database schema.

## Licensing

The packaged build checks a signed offline license before rendering the ERP. The license is bound to a generated machine ID and an expiry date. Before commercial release, replace the placeholder Ed25519 public key in `electron/security/license.js` with ABLECT's real public key. Never ship the private key.

## Windows build

```powershell
npm ci
npm run build
npm run package:win
```

The NSIS installer is written to `release/` with a name similar to `Ablect-Business-Suite-<version>-Setup.exe`.

## Release checklist

- Build on a clean Windows machine.
- Verify database auto-creation and migrations.
- Complete the first-run wizard.
- Complete repeated sales and verify unique invoice numbers.
- Test concurrent checkout and rollback behavior.
- Test login/session expiry/password change.
- Test invalid, expired and wrong-machine licenses.
- Verify `%APPDATA%/AblectBusinessSuite/error_log.txt`.
- Verify packaged startup loads `dist/index.html` without Vite.
- Test the installer on clean Windows 10/11.
- Back up and restore the customer's database before handover.
